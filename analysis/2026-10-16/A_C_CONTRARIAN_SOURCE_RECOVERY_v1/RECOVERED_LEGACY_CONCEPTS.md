## Identity rule

This file records only historical definitions that can be supported by surviving conversation/source evidence. It is **not executable model reconstruction**. Missing normalization, scoring, tie-break, weights, scripts, or selection details are not filled in from hindsight.

## Model A

### Earliest recoverable conceptual form

Late-September project records describe A as the pattern/statistics layer using the full history as the main body and recent windows as comparisons. Recovered signal inventory includes:

- long-term full-history frequency
- recent 10/30/50/100 frequency/change
- current nonappearance/gap
- sum
- odd/even
- low/high
- consecutive-number structure
- ending digits/repeated endings
- pair relationships
- later discussion also contemplated triple/3-number relationships

A September 27 formulation described candidate scoring conceptually as number-level score + structure score + pair structure + recent/long-term balance. No numeric formula survives for that formulation.

### September 30 weighted prototype recovered

A later conversation contains an explicit **initial** A weight proposal:

- long-term frequency: 35%
- recent 100 draws: 25%
- gap: 20%
- pair: 20%

The same record says these were initial, unvalidated values before backtest optimization. It does **not** preserve the component normalization formula, exact pair score, tie-breaking, candidate-selection code, script name/hash, or stable model version. Therefore this weight vector is recovered as historical metadata only and is not authorized as an executable legacy A model.

The surrounding conversation is internally inconsistent about execution: some assistant messages claimed numerical walk-forward results, while other messages in the same period explicitly said A/B/C had not actually been run. Those numerical claims are therefore not accepted as authoritative execution evidence.

**Recovered status:** conceptual definition + one historical prototype weight vector recovered; exact executable A not recovered.

## Model C

The strongest consistent historical definition is not a fixed numeric equation. The recovered rule is:

> C uses the A pattern layer, but only variables/signals that repeatedly survive B historical holdout/backtest validation are allowed into the combined decision layer; visually unusual structures are not removed merely because they look unbalanced.

Related wording from September 28 says A/B common-support signals are reflected in C and C-disfavored structures are preserved in a separate contrarian pool for validation. Later project guidance on October 2 further clarified that A/B/C should be independently modeled and not reduced to a blind A+B arithmetic mixture.

No historical numeric C weights, score-normalization formula, tie-break, script/hash, stable version identifier, or reproducible original walk-forward source survives.

**Recovered status:** decision principle recovered; exact executable C not recovered.

## Contrarian / 역발상

The historical contrarian concept is recoverable as a validation policy rather than a score formula. It says not to discard unusual structures for aesthetics and to keep them as separately tested opposite hypotheses. Recovered examples include:

- consecutive-number patterns
- concentration in one range/bucket
- odd/even skew
- low/high skew
- repeated ending digits
- extreme sums
- tight clustering or unusually spread combinations

The old three-line workflow discussion also assigned one role to a separately validated contrarian/opposite-hypothesis candidate, but no historical scoring formula or executable selector survives.

**Recovered status:** hypothesis/portfolio role recovered; exact executable contrarian model not recovered.
