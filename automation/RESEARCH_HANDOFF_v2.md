# Daily research execution v2

The authoritative project is GitHub `main`. Use the existing checkout; no Git worktree is needed. Preserve root `AGENTS.md`, `LOTTO_PROJECT_PROTOCOL.md`, all frozen research and raw data. Read both root rules completely before new research, then recent results, failure/hypothesis registries, correlation records and the research queue. Do not invent a recovered A/C model or repeat completed B/MC/H001/H002/regime tests as a new daily study.

## Running and validation

Python 3.12 and NumPy 2.3.5:

```bash
cd /workspace/lotto-data
source /workspace/lotto-onboarding/.venv/bin/activate
python -B automation/check_environment_v2.py
python -B -m unittest discover -s automation/tests_v2 -p 'test_*.py' -v
OPENBLAS_NUM_THREADS=2 python -B automation/daily_research_v2.py
```

The runner records the actual Asia/Seoul date and consumes the first unfinished registered question in `research_queue_v2.json`. Completed questions are skipped across dates; a scientific recipe signature also rejects renamed copies, regardless of cosmetic title/date/source changes. Every scientific job freezes its question, input SHA-256, source code and parameters before calculation; preserves a complete executable source copy; produces numerical CSV/report; and checks independent prediction/selection replay plus existing-file hashes. Outputs are staged in a new directory and promoted to a new `analysis/<date>/<task_id>` path only after validation. Existing files are never overwritten.

Readiness checks are MAINTENANCE/RECHECK, not a new study. Research completion requires positive executed-case counts, valid source/input identity, verification PASS, complete hashes and all four report sections. A missing package/cache triggers the next independent registered question. The exact tail-power job uses only the standard library and no model/cache/data network, so it remains executable if empirical model prerequisites fail. Failed attempts are retained with their diagnosis.

## Automatic workflow

`daily-lotto-research-v2.yml` schedules a run at 09:00 Asia/Seoul (00:00 UTC); GitHub can delay a scheduled start. Ordinary pushes of execution code run validation only. Manual/scheduled events and an explicitly marked `[run-daily-research-v2]` validation push execute one new registered study, commit only its new result directory and push normally. There is no force push. Failed runs preserve recovery artifacts and do not commit a false completion.

The old `daily-lotto-study.yml` and dated `daily_study_runner.py` are historical/manual paths and are not used by this new schedule. They remain unchanged to preserve the previous automation/version history; use v2 for new work. Do not edit the old trigger as a way to run a new v2 question.

## Backlog and research continuity

The registered queue is finite. It is not a claim that an unlimited number of new hypotheses can be generated by these deterministic scripts. When all questions are completed, the runner returns `NO_NEW_STUDY` with nonzero exit status; it never relabels yesterday's study as new. An agent continuing the project must then use the mandatory research-priority/failure registry to design and freeze the next independent question, add a new version/implementation, validate it and register it before execution. Do not stop an agent-led daily task at queue exhaustion if another independent research question can be executed.

The current empirical jobs are deliberately pinned retrospective experiments on the verified 1..1245 snapshot. Their daily execution date is not a claim that this snapshot has been externally refreshed. New draw data require a new validated version/provenance; keep old snapshots unchanged. Exact-power calculations are analytic hypothetical-effect studies, not evidence that a forecast achieves the effect.

All results remain POST_HOC_EXPLORATORY until a genuinely pre-draw registered future evaluation succeeds. No future ticket or purchasing recommendation is generated by these jobs. Future model performance, queue depletion and hosted-workflow activation must be reported distinctly from current local test success.
